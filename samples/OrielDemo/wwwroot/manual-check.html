托盘与通知

托盘图标在任务栏通知区（可能被收进 ^ 里）。悬停看 tooltip； 左键或右键点它都应弹出菜单（操作台上左键也弹，免得"点了没反应"难判断）， 点菜单项会以蓝色出现在日志里。通知是右下角横幅，点横幅本体应出现「通知点击」。
「移除托盘」→ 图标应立刻从通知区消失；「重建托盘」→ 图标重新出现、菜单照常。 这两项验的是原生资源真的被撤销又建立——Windows 上"进程没了图标还留着"（幽灵图标） 就是这么来的。
点击通知不会有回调——未打包应用的 toast 激活需要开始菜单快捷方式携带 AUMID 并注册 COM 激活器，那是打包器的职责，所以三平台在这一点上如实一致（都不回调）， Id 目前只是给通知打标签用。
横幅没出现时先看日志那一行：写「已提交给系统」说明本库已经交出去了， 去设置 → 系统 → 通知里看 OrielDemo 是否被关掉、专注助手/免打扰是否开着； 写「提交失败」才是实现侧的问题。

菜单

本窗口是无边框窗口：应用菜单在 Windows 上按设计跳过—— 预期是「没有菜单栏，也不报错」（客户区铺满时菜单栏会被盖住，与其设了看不见不如明确跳过）。 上下文菜单弹在鼠标位置；Windows 上它会阻塞消息循环直到你选择或取消，这是原生行为。

全局快捷键

注册后按 Ctrl+Shift+F12——焦点在别的程序上也要有反应才算全局。 触发会以「快捷键触发」出现在日志里。

内建右键菜单

默认策略是只保留剪切 / 复制 / 粘贴。内建菜单本来还带着「后退 / 前进 / 刷新 / 另存为 / 打印 / 检查元素」，对应用窗口来说多数是噪音——「刷新」在单页应用里会丢整页状态， 「另存为」存下来的是一份依赖外部资产的 HTML 外壳。 留下的这三项是只有原生侧能给的：粘贴要把系统剪贴板内容送进页面， 页面自己没这个权限。

改完下次右键即生效，不用重启窗口。验证最直接的地方是下面这个输入框： 输入些文字 → 选中 → 右键。

对话框

打开对话框的类型下拉应有两项（文本文件 / 所有文件）；多选要返回全部路径。 保存时输入不带扩展名的名字，落盘文件名应自动带上 .txt。 选文件夹在 Windows 上不支持初始目录（老 API 的已知取舍）。

Shell（系统集成）

最后一项传 file:///etc/passwd 与裸路径，必须返回 false 且不应有任何窗口弹出来——这是安全边界的检查，比「能用」更值得看。

开机自启

Windows 写 HKCU\Software\Microsoft\Windows\CurrentVersion\Run，可在 regedit 里核对同名值。验证完请点「禁用」，别把自启项留在系统里。

拖放

从资源管理器拖 1 个文件 / 多个文件 / 一个文件夹 进窗口，路径应出现在日志里；拖一段选中的文本则不应触发（只受理文件 URL）。
